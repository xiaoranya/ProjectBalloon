## 数据库集成测试（本轮真的跑了）

`docker run -d --name pb-test-pg -e POSTGRES_PASSWORD=balloon -e POSTGRES_USER=balloon
-p 55432:5432 postgres:16-alpine`，然后：

```
DATABASE_URL=postgres://balloon:balloon@127.0.0.1:55432/balloon \
  cargo test -p project-balloon-api --lib -- --ignored --test-threads=2
```

**必须限制 `--test-threads`**：每个 `#[sqlx::test]` 都会新建一个数据库并跑完整
迁移，并发数一高就批量失败（默认线程数下 40 个用例挂，2 线程下全过）。这不是
代码问题，别误判。

Redis 相关 4 个用例另起 `redis:7-alpine`（端口 56379），设
`PROJECT_BALLOON_TEST_REDIS_URL`；`paused_redis_returns_a_bounded_cache_miss`
还要 `PROJECT_BALLOON_TEST_REDIS_CONTAINER`（它会 pause/unpause 容器）。

结果：90 + 4 全过。**测试抓到一个真回归**：P2-68 用
`INSERT ... SELECT ... WHERE NOT EXISTS` 来阻止「版本 5 却新建行」，但
`ON CONFLICT DO UPDATE` 只对真正插入的行触发，于是所有更新都返回 None → 409。
正确做法是把这个判断放到语句之前（查询是否存在），SQL 仍用 `VALUES`。
教训：`ON CONFLICT` 与「条件插入」不能混用；改动 upsert 一定要跑 DB 测试。

`ssh -T git@github.com` 报 `Bad owner or permissions on
/etc/ssh/ssh_config.d/20-systemd-ssh-proxy.conf`，加 `-F /dev/null` 越过配置后
直接被对端关闭连接。走 HTTPS + gh 的凭据助手可行：

```
gh auth setup-git
git -c 'credential.helper=!gh auth git-credential' \
    -c url."https://github.com/xiaoranya/ProjectBalloon.git".insteadOf="git@github.com:xiaoranya/ProjectBalloon.git" \
    push -u origin <branch>
```

`insteadOf` 只对本条命令生效，不改 `.git/config`，`-u` 照样把 upstream 记成 `origin/<branch>`。
以后在这个环境推代码直接用这条，别再试 SSH。
