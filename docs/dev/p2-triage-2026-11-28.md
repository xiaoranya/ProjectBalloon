## 五、需要你拍板的 6 件事

1. **S1（P2-08/20/60）** 把实时入队移出业务事务，等于承认「实时事件可丢、业务不可回滚」。这是语义变更，改完 contests/resolver/awards/presentation/submissions 五处都可能不再 500。接受吗？还是保留现状只加观测？
2. **P2-19 幂等键** 要新迁移 + 前端重试逻辑配合，且旧客户端不带 header 时行为不变。本轮做还是留到 API 契约版本升级一起做？
3. **P2-90 补 CHECK** 新迁移不可回滚，历史数据可能违反（尤其 `submissions.language` 与 `runs.verdict`）。是先写数据普查 SQL 再决定，还是直接 `NOT VALID` 落地？
