# 编码风格

本文档定义 Rust 工作区与现有 Vue 前端的编码规则。

## 通用规则

- 优先选择简单、显式的代码，而不是聪明的抽象。
- 按功能组织业务代码，并保持依赖方向可见。
- 为不变量、安全边界与运维约束添加注释；不要复述语法。
- 不要将公共网络依赖引入运行时行为。
- 将正式比赛行为视为可审计且可恢复的。
- 将机密排除在源代码、日志、测试快照与示例之外。
- 声明稳定的工具链 channel 与最低 Rust 版本，并提交 `Cargo.lock` 以实现可复现的离线构建。发布镜像必须记录所使用的确切编译器版本。

## Rust 后端

后端技术栈：

- 仓库固定稳定工具链上的 Rust 2024 edition。
- Tokio 与 Axum。
- 搭配 PostgreSQL 的 SQLx。
- Redis 使用 `redis`。
- RabbitMQ 使用 `lapin`。
- RustFS/S3 兼容对象存储使用 `object_store`。
- 外部线格式使用 Serde。
- 结构化诊断使用 `tracing`。

### 工作区边界

- `apps/api` 拥有 HTTP 路由、认证提取、应用启动与 API 托管的后台任务。
- `apps/judge-worker` 拥有 Judge 任务消费与沙箱编排。
- `crates/domain` 包含纯类型、校验、计算与状态转换。它绝不能依赖 Axum、SQLx、RabbitMQ、Redis 或 S3。
- `crates/contracts` 包含显式版本化的 AMQP 与事件载荷。
- 不要为每个实体或业务功能创建一个 crate。只有在确实形成编译、部署或依赖边界时才添加 crate。

### 类型与领域规则

- 使用 `ContestId`、`SubmissionId`、`JudgementId` 等 newtype，而不是在系统中传递无关的原始 ID。
- 使用枚举表示有限状态与判定。显式解析未知外部值；不要静默映射为默认值。
- 将状态转换规则放在领域类型或纯领域函数上。
- 当不变量不同时，保持 HTTP 请求 / 响应类型、数据库行与领域对象相互区分。
- 在不需要所有权时优先使用借用输入（`&str`、切片、引用），但不要仅为避免进程边界的小克隆而增加生命周期复杂度。
- 在持久化与协议边界使用 UTC 时间戳。

### 错误

- 使用 `thiserror` 定义可恢复的库与领域错误。
- 仅在二进制启动、操作员命令或任务监督边界使用 `anyhow`，这些地方调用方不需要匹配单个变体。
- 在 HTTP 适配器中将错误映射为单一稳定的 API 错误信封。
- 绝不向客户端返回 SQL、对象键、凭据、内部路径或原始依赖错误。
- 生产请求 / 任务路径中禁止 `unwrap`、`expect`、`panic`、`todo` 与 `unimplemented`。经过严格论证的启动不变量可以使用带可操作消息的 `expect`。

### 异步与并发

- 绝不在无关的 `.await` 点之间持有同步 mutex 保护或数据库事务。
- 使用有界通道与显式背压。
- 监督生成的 task；无人观察的分离 task 不是后台任务策略。
- 将 CPU 密集工作与阻塞的文件系统 / 进程操作放在 `spawn_blocking` 或专用有界 worker 池之后。
- 对数据库、Redis、RabbitMQ、S3、CUPS 与沙箱操作应用显式超时。
- 将取消与关闭信号传递给消费者与长时间运行的任务。

### HTTP 与应用代码

- Handler 提取并校验输入、授权请求、调用一个应用操作并转换其结果。它们不包含 SQL 或多步比赛逻辑。
- 在单一类型化应用状态下按功能组合路由器。
- 使用类型化的认证 / 授权提取器与显式策略函数；不要在 handler 中散落字符串角色检查。
- 迁移时保留 `docs/api/openapi.yaml` 中已评审的行为。契约变更需要显式的兼容性决策与测试。
- 对浏览器变更保留 Cookie 会话认证与 CSRF 保护；未经单独的架构决策，不要用 JWT 替换它。

### 持久化与消息

- PostgreSQL 是真相来源；Redis 条目必须可重建。
- 使用 SQLx 参数绑定。动态标识符或排序子句必须来自封闭枚举，绝不能直接来自请求字符串。
- 保持应用操作中的事务边界可见。
- 通过事务性 outbox 发布 Judge 与其他持久任务。不要执行无协调的数据库写入 / RabbitMQ 发布双重写。
- 消费者必须幂等。仅在持久结果或重试 / 死信路径建立后 ACK。
- Trait 用于有意义的可替换边界或测试接缝。不要按惯例为每个表创建 repository trait。

## 前端

前端技术栈：

- Vue 3。
- TypeScript。
- Vite。
- Element Plus 作为默认 UI 组件库。

前端准则：

- 清晰分离 contestant、admin、screen、live、resolver 与 awards 路由。
- 绝不在公共、screen 或 live 页面渲染敏感字段。
- 针对 `docs/api/openapi.yaml` 生成或校验类型化 API 客户端。
- 确保页面在无 CDN 资源的离线局域网中可用。
- 内置字体、图标、编辑器资源、MathJax/KaTeX 与语法高亮资源。
- 使用按需 Element Plus 导入以保持离线包体积小。
- Screen、live 与 resolver 页面可以使用自定义全屏布局，但仍必须避免外部资源。

## 数据库迁移

- 在 Rust 重置中对所有架构变更使用 SQLx 迁移。
- alpha 阶段：schema 是单个合并迁移（`migrations/0001_initial.sql`）；在部署从零重建数据库的前提下，可对其进行破坏性编辑。
- 在首个非 alpha 版本发布前，冻结该合并迁移，之后通过新增前向迁移而不是编辑它来演进。
- 在官方数据存在后避免破坏性迁移，除非备份与恢复已经过测试。
- 为比赛范围查询添加索引，尤其是 submissions、judgements、scoreboards、print tasks 与 balloon tasks。
- 将大对象存储在 RustFS，并将其哈希、版本与元数据存储在 PostgreSQL。
- 提交 SQLx 离线查询元数据并在 CI 中验证。

## Judge

- 将提交的源码、测试数据归档与编译器输出视为敌意输入。
- 使用类型化沙箱规范；绝不从参赛者可控字符串构造 shell 命令。
- 正式部署中不挂载 Docker socket，也不授予特权权限。
- 在诊断中保持编译器 / 运行时版本可见。
- 限制所有输入、输出、日志、归档、进程与执行大小。
- 通过 RAII guard 清理工作目录，使提前返回也不会跳过清理。

## 测试与质量门禁

- 保持纯领域测试确定且无基础设施依赖。
- 针对 PostgreSQL 测试 SQL，而不是替换为其他数据库。
- 为 AMQP 消息、SSE 事件与重要 API 响应添加契约 fixture。
- 测试重试、重新投递、重复投递、超时、取消与关闭行为。
- 必需检查为 `cargo fmt --check`、warnings 视为错误的 Clippy、工作区测试、使用编译期查询宏时的 SQLx 元数据验证，以及依赖 / 许可证审计。
- 默认禁止不安全 Rust。任何例外都需要架构决策、文档化的不变量与针对性测试。

## 文档

- 架构、部署、安全或比赛工作流变更时更新文档。
- 保持运维文档可执行：包含输入、命令、验证与故障处理。
- 避免记录机密或真实凭据。
