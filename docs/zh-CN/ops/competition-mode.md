# 比赛模式

本页面向在 `competition` 部署模式下运行 ProjectBalloon 的运维人员：现场比赛中每个机位是固定终端，队伍用配对码登录，而不是使用账号密码。

## competition 模式的作用

在环境文件中设置 `PROJECT_BALLOON_DEPLOYMENT_MODE=competition` 并重启 API 服务：

- 强制非重叠比赛日程：任意两场比赛不能重叠，同一时间只能有一场比赛处于进行中。
- 启用 IP 绑定终端配对：队伍在 `/login` 用配对码从分配的工作站登录。
- 停用日常功能：公开题库、训练计划、日常练习、虚拟比赛、自助注册与管理端练习页。

## 准备终端

- 为每台参赛机分配浏览器可达的静态 IP。
- 记录每台机器的机位号与 IP；之后需要在管理端登记。

## 配置绑定

1. 以拥有 `CONTEST_MANAGE` 的管理员身份登录，打开 `/admin/competition`。
2. 登记每个终端：IP 地址、机位号与可选备注。
3. 加载该比赛的绑定列表。
4. 把终端绑定到队伍；队伍必须已在比赛名单中。
5. 复制仅显示一次的配对码并交给对应机位。

完整流程见[管理员指南](../user/admin/README.md)。

## 赛前验证

- 确认恰好一个比赛处于 `RUNNING`/`PAUSED` 且在日程范围内。
- 从测试终端打开 `/login`，选择配对码方式并登录。
- 确认登录的队伍与机位匹配、比赛为预期的那一场。
- 排练结束后，为使用过共享配对码的机位轮换配对码；轮换会使现有会话失效。
- 确认日程完整性检查通过（无重叠比赛）。

## 运行期行为

- 配对码仅在绑定或轮换时显示一次，之后无法再查询。
- 会话绑定到终端 IP；来自其他 IP 的请求会被拒绝，队伍必须从分配机器登录。
- 会话在比赛结束时失效。
- 轮换配对码或撤销绑定会立即使该机位的会话失效。

## 故障排查

- “No contest is currently active”：比赛不在日程范围内，或状态不是 `RUNNING`/`PAUSED`。
- “This IP address is not bound”：终端未登记/未启用，或没有当前进行中比赛的绑定。
- “Pairing code is invalid”：请核对配对码；若已泄露，请轮换。
